# 실패 연구 자료

라운드 작업 폴더에서 실행한다.

```sh
python3 failure-lab/extract.py
```

Python 3.10 이상과 로컬 Git 이력이 필요하다. 파이썬 표준 라이브러리만 사용한다. 입력과 Git은 읽기 전용이며 네트워크 호출은 없다. 가게가 기록을 추가하면 파일별 종료 시점이 달라질 수 있다.

## 경계와 한계

- 바쁜 답변, 실패한 호출, 버전 회귀, 만료 원장 행은 서로 다른 관측 단위다. 같은 판매 기회에서 여러 사건이 생길 수 있다. 매입 실패는 보호 중단과 창 바깥의 정상 거절도 포함한다.
- talk는 react보다 늦게 시작하고 도착 시각·task ID·데이터 파트가 없다. 결제서를 보냈다는 말과 전달 영수증을 구분한다. defer_timeout은 동일 본문과 시각을 맞춘 재호출이 보이는 경우다.
- agent_state는 시각상 직전 또는 동일 시각 mind 호출이며 동시 처리에서는 실제 원인 스텝과 다를 수 있다. preceded_by는 주제나 시각이 가까운 기록을 가리킨다.
- 비용은 원장의 expire.data.cost를 합산했다. 결제서 가격은 잃은 매출로 집계하지 않았다. 잠금 비용은 추정 3시간을 합산하지 않고, 발급 시각과 이후 같은 기존 발급이 재발급을 막은 시각이 확인된 고등어 한 단위의 경과만 하한으로 기록했다.
- 조사·판매·수선 비율은 스텝 비율이다. 모델 생각 시간, 도구 실행 시간, sleep 시간을 활동별로 정확히 분리할 수 없다.
- 개입 전후 비교에서 요청 내용·재고·동시 개입은 통제하지 않았다. 넛지와 주인 채팅의 주제는 단일 토픽 휴리스틱으로 정했다. 넛지 로그에 대응하는 앱 메시지는 중복 집계하지 않는다. 주인 채팅은 질문·승인·단순 응답도 포함한다. 넛지는 전송 표기 시각을 사용한다. 키트 시작 행은 시도까지 포함한다. goal 커밋 시각과 적용 시각에는 간격이 있다.
- Git에서 접근 가능한 goal과 소스만 비교했다. 미커밋 변경 내역, 시험의 모든 입력, 과거 전체 프롬프트, 모델에게 실제 전달된 관찰 전문, 공개 원장 API의 현재 응답은 확인하지 못했다. HANDOFF와 보드는 조사 단서로 사용했다.
- 원본 행을 수정하거나 재정렬하면 지정 검토 사례와 사건 ID가 달라진다. 출력에는 원본 위치만 넣으며 결제서 원문이나 비밀값을 복제하지 않는다.
